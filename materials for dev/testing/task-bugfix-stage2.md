## БАГ 1 — Авторизация: PIN не проверяется

**Проблема:** Любой PIN пускает в систему. Ввёл 0000 на Папу — зашёл. Это значит что `bcrypt.compare()` не работает или вообще не вызывается.

**Что проверить в коде:**
1. Открой `server/src/routes/auth.ts`
2. Найди логику сравнения PIN — там должен быть `bcrypt.compare(pin, user.pinHash)` и только если он вернул `true` — выдаётся токен
3. Проверь seed: открой `server/prisma/seed.ts` — там должен быть `bcrypt.hash("1111", 10)` для Папы, `bcrypt.hash("2222", 10)` для Мамы, `bcrypt.hash("3333", 10)` для Бабушки. Если там хранится сырая строка "1111" — это причина бага.

**Как починить:**
- Убедиться что seed хеширует PIN через bcrypt перед сохранением
- Пересеять базу: `npx prisma db seed` (предварительно очистить таблицу User)
- В роуте login убедиться что идёт именно `bcrypt.compare`, а не `pin === user.pinHash`

**Проверка после фикса:**
```bash
# Должен вернуть токен
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"role": "papa", "pin": "1111"}'

# Должен вернуть 401
curl -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"role": "papa", "pin": "0000"}'
```

## БАГ 2 — Авторизация: сессия не сохраняется

**Проблема:** Каждый раз при открытии `/admin` снова запрашивается PIN. Должно быть иначе: ввёл PIN один раз — система запомнила, при следующем входе сразу попадаешь в панель.

**Логика которая должна быть:**
- При успешном login → JWT токен сохраняется в `localStorage` с ключом `station_token` и `station_role`
- При открытии `/admin` → фронтенд проверяет `localStorage.getItem('station_token')`
- Если токен есть и не истёк → сразу переходит на `/admin/event` без запроса PIN
- Если токена нет → показывает PIN-экран
- При нажатии кнопки выхода (→) → `localStorage.removeItem('station_token')` + `localStorage.removeItem('station_role')` → редирект на `/admin`

**Что проверить и починить в коде:**
1. В компоненте AdminLogin (или как он называется) — после успешного логина должен быть:
   ```javascript
   localStorage.setItem('station_token', token);
   localStorage.setItem('station_role', role);
   ```
2. В useEffect при монтировании AdminLogin — проверка:
   ```javascript
   const token = localStorage.getItem('station_token');
   if (token) navigate('/admin/event');
   ```
3. Кнопка выхода — очистка localStorage + navigate('/admin')
4. Все API-запросы с авторизацией должны брать токен из `localStorage.getItem('station_token')` и добавлять в заголовок `Authorization: Bearer {token}`

**Проверка после фикса:**
1. Зайти на `/admin`, ввести PIN 1111 как Папа → попасть в панель
2. Закрыть вкладку, открыть снова `/admin` → должен сразу попасть в панель без PIN
3. Нажать кнопку выхода → попасть на PIN-экран

## БАГ 3 — События записываются от имени Папы независимо от роли

**Проблема:** Зашёл как Мама, добавил событие — в журнале написано «ПАПА».

**Причина:** Скорее всего `authorId` в роуте `POST /api/events` захардкожен или берётся неправильно из JWT.

**Что проверить:**
1. Открой `server/src/routes/events.ts`
2. При создании события `authorId` должен браться из декодированного JWT: `request.user.userId` (или как называется поле в payload)
3. JWT payload при логине должен содержать `{ userId: user.id, role: user.role }`

**Как починить:**
- Убедиться что middleware для проверки JWT декодирует токен и кладёт данные в `request.user`
- В `POST /api/events` использовать `authorId: request.user.userId`

**Проверка после фикса:**
```bash
# Получить токен Мамы
MAMA_TOKEN=$(curl -s -X POST http://localhost:3001/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"role": "mama", "pin": "2222"}' | python3 -c "import sys,json; print(json.load(sys.stdin)['token'])")

# Добавить событие от Мамы
curl -X POST http://localhost:3001/api/events \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $MAMA_TOKEN" \
  -d '{"sphere": "study", "type": "good", "weight": 10, "comment": "Тест от мамы"}'

# Проверить журнал — должно быть author.role = "mama"
curl http://localhost:3001/api/events | python3 -m json.tool | grep -A2 "author"
```

## БАГ 4 — Формула энергии считает неправильно (линейно вместо логистической кривой)

**Проблема:** Добавили 50 баллов — показывает 50. Добавили ещё 50 — показывает 100. Это линейная формула, а должна быть логистическая кривая.

**Правильная формула:**
```
E = (200 / (1 + e^(-S/k))) - 100
```
Где:
- `S` — сумма весов всех событий за последние 7 дней
- `k` — делитель кривой (из настроек, по умолчанию 30)
- `E` — итоговая энергия, всегда строго между -100 и +100

**Примеры правильных значений (при k=30):**
| S (сумма баллов) | E (энергия) |
|-----------------|-------------|
| 0 | 0 |
| +30 | +46.2 |
| +50 | +58.7 |
| +100 | +76.2 |
| +150 | +85.8 |
| -50 | -58.7 |

**Показатели сфер (Учёба, Уважение, Фокус, Семья) — ОТДЕЛЬНЫЕ формулы:**
Каждая сфера считается по той же формуле, но только по событиям своей сферы. Потом нормализуется в диапазон 0–10:
```
sphereScore = ((E_сферы + 100) / 200) * 10
```

**Общая энергия станции — среднее четырёх сфер:**
```
E_общая = среднее(E_учёба, E_уважение, E_фокус, E_семья)
```
Это значит: если хорошо только по учёбе, а остальные три на нуле — общая энергия будет около +12, а не +46.

**Что проверить в коде:**
Открой `server/src/services/energy.ts` — там должна быть формула с `Math.exp`. Если там просто `sum / total` или `events.reduce((acc, e) => acc + e.weight, 0)` без `Math.exp` — формула неправильная.

**Правильный код:**
```typescript
export function calcEnergy(sumS: number, k: number): number {
  const E = (200 / (1 + Math.exp(-sumS / k))) - 100;
  return Math.round(E * 10) / 10;
}

export function calcSphereScore(sumS: number, k: number): number {
  const E = calcEnergy(sumS, k);
  return Math.round(((E + 100) / 200) * 10 * 10) / 10;
}

// В station.ts:
// 1. Для каждой сферы отдельно посчитать sumS за 7 дней
// 2. Применить calcEnergy к каждой сфере
// 3. Общая E = среднее четырёх E_сферы
// 4. sphereScore = нормализация каждой E в 0–10
```

**Проверка после фикса:**
```bash
# Сбросить базу событий (удалить все)
# Добавить одно событие +50 по учёбе
curl -X POST http://localhost:3001/api/events \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"sphere": "study", "type": "good", "weight": 50, "comment": "формула тест"}'

curl http://localhost:3001/api/station
```
**Ожидаемый результат:**
- `spheres.study` ≈ 7.9 (не 10.0!)
- `energy` ≈ +14.7 (среднее: study ~+58.7, остальные три по 0 = 58.7/4 ≈ 14.7)

## БАГ 5 — Сундуки не добавляются

**Проблема:** При попытке добавить награду или последствие через `/admin/chests` — ничего не происходит или ошибка.

**Что проверить:**
1. В DevTools → Network: при нажатии «СОХРАНИТЬ» какой запрос уходит? Какой ответ возвращает сервер?
2. Если 401 — проблема с токеном (фронт не передаёт Authorization header)
3. Если 400 — неправильное тело запроса (проверить что фронт отправляет `chestType`, `icon`, `level`, `title`)
4. Если 500 — ошибка на сервере (смотреть `docker-compose logs server`)

**Правильный запрос:**
```bash
curl -X POST http://localhost:3001/api/chests \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"chestType": "reward", "icon": "🎮", "level": 1, "title": "1 час игр"}'
```
Должен вернуть HTTP 201 и созданный объект.

Починить как в API так и на фронте — убедиться что при сабмите формы на `/admin/chests` уходит правильный POST-запрос с токеном из localStorage.
